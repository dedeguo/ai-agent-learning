# 第一课：Token、ID 与 Embedding

学习目标：区分文本片段、整数编号与向量表示，读懂 embedding 查表。

## 1. 文本怎样变成模型输入

```text
文本 → tokenizer → token IDs → embedding 查表 → X
```

Token 是 tokenizer 处理的基本单位，可以是字、词、子词或字节片段，不必对应一个完整单词。具体拆分取决于 tokenizer；本课用空格分词和手工词表演示流程，不代表真实大模型的分词规则。

给定玩具文本 `我 喜欢 学习`：

| token | token ID | 示例 embedding |
| --- | --- | --- |
| 我 | 0 | [1, 0, 0, 1] |
| 喜欢 | 1 | [0, 1, 0, 1] |
| 学习 | 2 | [0, 0, 1, 1] |
| 你 | 3 | [1, 1, 0, 0] |
| [UNK] | 4 | [0, 0, 0, 0] |

ID 只是词表中的索引。ID 为 3 不意味着它比 ID 为 1 的 token 更重要，也不能用 ID 的差值判断语义距离。

## 2. Embedding 是查表

把所有向量排成表 `E`，形状是 `(词表大小, d_model)`。对每个 ID 取出对应行：

```python
ids = np.array([0, 1, 2])
X = E[ids]
# E: (5, 4)，ids: (3,)，X: (3, 4)
```

这里序列长度 `n=3`，每个 token 有 `d_model=4` 个特征。**X 的每行对应一个位置的 token，每列对应一个特征维度。** 序列长度和向量维度是两回事。

真实模型的 embedding 表通常是可学习参数，由训练更新。上面的向量是手工指定的；各维没有预设的“主语”“动词”含义，也不能据此声称模型理解了语义。

同一 token 在输入查表阶段得到同一向量。例如 `我 喜欢 我` 的第 1、3 行相同。后续加入位置信息并经过 Attention 后，各位置的表示可以不同。

本课把未登录词映射到 `[UNK]`，这是玩具实现的选择；实际 tokenizer 的处理策略可能不同。
