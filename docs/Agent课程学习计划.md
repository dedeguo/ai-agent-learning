# Agent 课程学习计划

整理日期：2026 年 10 月 8 日。

本计划衔接[四周基础学习计划](学习计划.md)，以教育智能体、CourseMind 和软件项目实训为应用方向。采用 **CMU 11-768 视频学习原理，Stanford CS329Z 作业练习系统开发** 的路线。先完成一个可评测的应用，再按研究需要进入模型训练。

默认每周投入 6～8 小时，主线约 8 周，对应项目第 5～12 周。周次按实际学习进度推进，不代表已经完成前四周；遇到作业较难时可延长。学习周次与大学课程的授课周次不同。

## 开始前的检查

- [ ] 能解释 token、Attention、causal mask 和自回归生成。
- [ ] 能区分训练时更新参数与调用 API 时推理。
- [ ] 能用 Python 调用模型 API、读写 JSON、处理异常。
- [ ] 能说明 RAG 的检索与生成过程。

如果理论部分仍不熟，继续完成第四周练习；不必等待 mini GPT 训练成功才开始 Agent 主线。前四周的概念学习也不等同于已有完整模型训练经验。

## 每周学习方法

每周安排两次课程学习、两次实践和一次复盘。参考分配：视频与幻灯片 2 小时，编码与调试 3～4 小时，评测与复盘 1～2 小时。先完成验收，再增加论文阅读；每讲精选一篇最相关的论文或源码即可。

每周留下三类证据：能独立解释的概念、可运行的代码、包含失败案例的实验记录。AI 可以辅助解释和调试，但提交到自己的学习项目中的代码应能逐段说明。

## 第 5 周 理解 Agent 并实现工具循环

**材料：**11-768 第 1、2 讲；CS329Z 的 Tool Use 主题。

理解模型、工具、环境和运行框架的分工。用底层模型 API 实现“请求模型 → 解析工具调用 → 执行工具 → 回传结果 → 继续决策”的循环。先使用一个简单计算工具和一个本地资料搜索工具。

**实践：**加入工具参数检查、最大步数、超时和异常反馈，记录每一步输入、输出与工具结果。暂不使用 Agent 框架。

**验收：**完成至少 5 个固定任务，覆盖正常调用、非法参数、工具异常和达到步数上限；能查看执行轨迹并解释停止原因。

## 第 6 周 上下文管理与检索

**材料：**11-768 第 3 讲；CS329Z 的 RAG 与 LLMs for Builders 主题。

理解历史消息、工具输出与检索结果如何占用上下文。用一小批熟悉的教学资料建立检索问答，比较关键词检索与已有向量检索方案。明确引用来源和信息不足时的行为。

**实践：**实现工具输出截断或筛选；在上下文接近预算时压缩历史。保留关键事实、来源和未完成任务，观察压缩是否丢失信息。

**验收：**保存至少 10 个问答案例，记录检索结果、回答、引用和失败原因；解释检索失败与生成失败的区别。

## 第 7 周 记忆与任务规划

**材料：**11-768 第 4、5 讲；CS329Z 的 Memory 与 Agent Design Patterns 主题。

区分当前会话状态、跨会话记忆和可复用技能。给助手加入可查看、修改、删除的少量持久记忆；为“查资料 → 生成教学活动 → 检查约束”一类任务加入明确的任务分解。

**实践：**比较不规划与先规划两种方式。先做单 Agent；多 Agent 作为后续实验，只有出现可衡量的收益才增加复杂度。

**验收：**用至少 5 个多步任务展示完成、失败或中途修正的轨迹；能解释哪些信息值得记忆、错误记忆如何纠正。

## 第 8 周 完成一个应用原型

**材料：**11-768 第 6、7 讲；[CS329Z 作业 1](https://github.com/cs329z/assignment1-harness)。

理解编码 Agent 与电脑操作 Agent 的环境和接口差异，精读 CS329Z 作业说明。建议完成官方企业邮件助手作业；若希望优先服务教育项目，可将其作为设计参考，构建教学资料助手，并明确这属于自定义项目，不是官方作业的完整复现。

**实践：**整合检索、工具、记忆、日志和人工确认环节，做出可重复演示的原型。文件和终端工具只访问实验目录；在增加工具前明确输入、输出和可操作范围。

**验收：**从干净环境按说明启动，完成 3 个端到端演示；列出支持的任务、限制和已知问题。若时间不够，延长本周，不用删掉关键错误处理来赶进度。

## 第 9 周 建立固定评测集

**材料：**CS329Z 的 Evaluation Fundamentals 与 LLM-as-Judge 主题；[11-768 作业 2](https://github.com/cmu-agents/assignment-2)。若对应课件尚未公开，先阅读官网指定材料并完成基线评测。

整理 20～30 个任务，覆盖直接问答、检索、多步任务、信息不足、工具失败和干扰输入。每个任务明确请求、环境、停止条件和评分规则。拆分开发集与保留测试集，避免用测试集反复调参。

**实践：**优先使用程序评分；开放回答可加入 LLM judge，并人工抽查评分与证据是否一致。

**验收：**输出基线报告，至少包含任务成功率、引用正确性、工具错误、时延、token 或成本。记录模型版本、配置、数据版本和运行日期，让结果可以复现。

## 第 10 周 用实验改进系统

**材料：**CS329Z 的 Optimization 与 Data Quality 主题。

从基线中挑选一个主要失败原因，比较提示修改、检索改进或上下文策略。每次只改变一个主要因素；采用相同任务和可比较的调用预算。

**实践：**至少做两组对照，记录改进和退步案例。对模型随机性敏感的任务重复运行，避免把单次结果视为稳定收益。

**验收：**报告质量、成本与时延变化；能说明哪种改动有效、在哪些任务上有效、有哪些局限。没有提升也是有效实验结果。

## 第 11 周 安全与可观察性

**材料：**11-768 Agent Safety 幻灯片；两门课程的安全、监控相关材料，随公开进度补充。

测试检索文档中的恶意指令、越界工具请求和错误参数。区分用户授权与资料内容，建立可检查的工具执行记录、失败日志和运行预算。

**实践：**加入至少 5 个安全或可靠性测试案例；对修改、删除、发送等有实际影响的工具明确人工确认方式。

**验收：**能够定位失败发生在哪一步，并证明工具操作范围和循环预算有效；报告测试覆盖范围，不把通过少量案例等同于完整安全保证。

## 第 12 周 整理项目与研究问题

冻结一版助手，在保留测试集上评测，整理运行说明、演示与结果。结合教育应用挑选一个可检验的问题，例如“记忆能否改善跨会话教学任务”或“自动评分与教师判断有多一致”。

**验收：**交付可运行项目、任务集、评分脚本、基线与改进对照报告，以及一页后续研究方案。方案应明确假设、对照、指标和成本预算。

## 后续选学 Agent 模型训练

完成主线后，再选学 11-768 第 8、9 讲及后续高级 RL、RL Systems 内容。先理解训练数据、轨迹、奖励与长程任务的关系，再决定是否做训练作业。

建议用 2～4 周补充一个小型 PyTorch 训练或 SFT 实验，掌握梯度、训练与验证划分、过拟合和 checkpoint；确认算力与成本后再进入 Agent RL。官方训练作业公开后，以实际说明为准，不提前假定所需 GPU 或预算。

只有当评测显示主要瓶颈可能来自模型能力，且有合适数据和奖励信号时，再投入训练。教育研究也可以先围绕检索、上下文、记忆、评测或人机交互开展。
