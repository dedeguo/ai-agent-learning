# 第二课：位置编码——让 Attention 使用顺序信息

本课目标：解释没有位置表示时交换 token 会发生什么，理解位置编码如何影响 QKV 和 Attention 输出，并区分序列长度与向量维度。

## 1. 先明确：整个序列参与计算，每个位置都有输出

以“我 喜欢 你”为例，将三个 token 的 embedding 按行排列：

```text
X = [E我; E喜欢; E你]       # (3, 4)，分号表示换行
Q = X @ Wq
K = X @ Wk
V = X @ Wv
```

假设 Wq、Wk、Wv 都是 `(4, 2)`，Q、K、V 就都是 `(3, 2)`。各位置共享投影参数，但这一步每行独立计算，还没有交换 token 信息。

随后计算单头 Attention：

```text
S = Q @ K.T / sqrt(2)     # (3, 3)：每个位置对所有位置的匹配分数
A = softmax_rows(S)       # (3, 3)：每行权重之和为 1
O = A @ V                # (3, 2)：每个位置汇集信息后的表示
```

S 的第二行是：

```text
[Q喜欢·K我, Q喜欢·K喜欢, Q喜欢·K你] / sqrt(2)
```

假设 softmax 后得到 `[0.2, 0.3, 0.5]`，那么：

```text
O喜欢 = 0.2 × V我 + 0.3 × V喜欢 + 0.5 × V你
```

如果 V我=`[1,0]`、V喜欢=`[0,1]`、V你=`[2,2]`，O喜欢就是 `[1.2,1.3]`。这些数值仅作示意。

这里的“喜欢的输出”指 O 中对应“喜欢”的一行向量，不是模型最终生成的文字。整个输出 O 仍然包含三个位置的向量。

**当前位置的输入决定自己的 Q；当前位置的 Attention 输出还依赖整个序列的 K、V。**

## 2. 没有位置编码，交换词语会怎样？

比较：

```text
我 喜欢 你
你 喜欢 我
```

同一个 token 查表得到的 embedding 相同。没有位置表示、mask 或其他顺序机制时，交换输入行，只会相应交换 Q、K、V 的行。

“喜欢”仍在中间，其 Q 不变。它对“我”“你”的匹配分数与权重跟着词的位置交换，V 也一起交换：

```text
原句：0.2 × V我 + 0.3 × V喜欢 + 0.5 × V你
新句：0.5 × V你 + 0.3 × V喜欢 + 0.2 × V我
```

加法顺序改变，结果不变，因此“喜欢”的 Attention 输出相同。

更一般地，输入行重排后，输出行按相同方式重排，这称为**置换等变**：

```text
MHA(X[order]) ≈ MHA(X)[order]
```

它不表示两个完整输出矩阵逐元素相同，而是对应 token 的输出相同、排列随输入改变。这里讨论的是没有顺序机制的 Attention；第四周的 causal mask 会改变这一前提。

## 3. 加入位置编码，让位置参与 QKV

一种直接的方法是给每个位置准备一个与 embedding 同维的向量：

```text
Z = X + P                # 两者都是 (n, d_model)
Q = Z @ Wq
K = Z @ Wk
V = Z @ Wv
```

相加不改变形状。P 绑定的是序列位置，交换词语后应按新的位置添加 P：

```text
我 喜欢 你：
[E我 + P[0]; E喜欢 + P[1]; E你 + P[2]]

你 喜欢 我：
[E你 + P[0]; E喜欢 + P[1]; E我 + P[2]]
```

“喜欢”的输入与 Q 仍然相同，但两侧 token 的输入不再只是互换。例如“我”从 `E我+P[0]` 变成了 `E我+P[2]`，其 K、V 可能改变。因此“喜欢”的注意力权重和最终输出也可能改变。

位置编码提供了使用顺序的线索；模型还需要通过训练学习如何使用它，不能仅凭加入 P 就认为模型理解了句意。

### 为什么不是只给 Attention 输出加 P？

比较：

```text
A：O = Attention(X + P)
B：Y = Attention(X) + P
```

A 让位置影响这一层的 Q、K、V 和注意力权重。B 的 P 在这一层 Attention 计算结束后才加入，因此不能影响这一层的注意力权重；它仍可能影响后续层。

需要区分前向计算与梯度：不能由 B 推断“Wq 的梯度与 P 无关”。如果 loss 根据 Y 计算，P 会影响 Y，并可能通过 loss 影响反向传播给 Wq 的梯度。

## 4. 正弦位置编码怎样计算？

本课采用固定的正弦位置编码，每两个特征维度使用一组频率：

```text
P[pos, 2i]   = sin(pos / 10000^(2i/d_model))
P[pos, 2i+1] = cos(pos / 10000^(2i/d_model))
```

| 变量 | 含义 |
| --- | --- |
| pos | token 在序列中的位置，从 0 开始 |
| d_model | 每个 token 的向量维度 |
| i | sin/cos 配对的编号，从 0 开始 |

当 d_model=4 时：

```text
P[pos] = [sin(pos), cos(pos), sin(pos/100), cos(pos/100)]
```

三角函数使用弧度。前三个位置约为：

| 位置 | sin(pos) | cos(pos) | sin(pos/100) | cos(pos/100) |
| --- | ---: | ---: | ---: | ---: |
| 0 | 0 | 1 | 0 | 1 |
| 1 | 0.8415 | 0.5403 | 0.0100 | 0.99995 |
| 2 | 0.9093 | −0.4161 | 0.0200 | 0.99980 |

前两维变化较快，后两维变化较慢，多种频率共同描述位置。位置 0 的编码是 `[0,1,0,1]`，不是全零向量。位置编码不是概率，也不是单词的语义 embedding。

位置表示也可以是可学习向量。RoPE 等方法在注意力计算中的 Q、K 上引入位置信息，并非所有位置方法都直接计算 `X + P`。

## 5. 上下文长度与这里的序列有什么关系？

```text
X 的形状 = (n, d_model)
            ↑      ↑
         token数  每个token的向量维度
```

通常所说的 128k 上下文窗口，描述模型一次处理时能够容纳的 token 数量上限，对应序列长度 n 的限制，不是 d_model 的大小。具体 token 上限与计数方式以模型文档为准。

上下文可能包含系统指令、历史对话、当前问题、工具返回内容以及生成的回答。窗口通常包含输入和输出；部分模型还计入推理 token。因此不能把 128k 理解为“输入满 128k 后，仍可额外生成任意长度的回答”。参见 [官方上下文窗口说明](https://developers.openai.com/api/docs/guides/conversation-state)。

读取输入时，模型处理已有序列；自回归生成时，逐个追加新 token。实际实现通常缓存已有 token 的 K、V，避免每次生成都重新计算整个序列。上下文长度也不意味着必须在内存中一次存储完整的 n×n 注意力矩阵，具体取决于实现。

位置表示负责表达“token 在哪里”，上下文窗口限制“序列可以有多长”；二者相关，但窗口大小不是由位置编码公式单独决定的。

## 6. 运行顺序对比实验

打开 [位置编码 Notebook](../../notebooks/week03/02_positions.ipynb)，或在项目根目录运行：

```bash
.venv/bin/python exercises/week03/02_positions.py
```

实验使用固定随机参数，不训练模型，先将 X 按 `[2,1,0]` 重排：

1. 不加位置编码：比较 `MHA(X[order])` 与 `MHA(X)[order]`，误差应接近浮点误差。
2. 加位置编码：比较 `MHA(X[order]+P)` 与 `MHA(X+P)[order]`，结果通常不同。前者按当前位置添加 P，后者重排已经计算好的输出。

## 7. 自查

1. 为什么“喜欢”的 Q 相同，不能保证它的 Attention 输出相同？
2. 不加位置编码时，为什么交换“我”“你”不会改变对应 token 的输出？
3. 交换 token 后，位置向量应跟着 token 移动，还是绑定当前位置？
4. d_model=4、pos=0 时，正弦位置编码是什么？
5. `(n,d_model)` 中哪一维与上下文长度有关？

答案要点：输出依赖所有 K、V；无顺序机制时权重与 V 同步重排，加权和不变；P 绑定当前位置；`[0,1,0,1]`；n。
