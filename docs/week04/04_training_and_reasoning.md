# 第四课：训练阶段与推理时计算

这些名称描述不同目标，不是所有模型都严格遵循的固定流水线。

| 阶段/方法 | 常见数据或信号 | 主要目标 | 是否更新参数 |
| --- | --- | --- | --- |
| 预训练 | 大量文本序列 | 学习预测下一 token，形成语言与知识表示 | 是 |
| SFT（监督微调） | 提示与示范回答 | 提高示范回答的概率，学习回答方式 | 是 |
| RLHF（人类反馈强化学习） | 人类偏好、奖励信号 | 通过强化学习提高符合偏好的回答的奖励 | 是 |
| DPO（直接偏好优化） | 同一提示的偏好/非偏好回答对 | 相对参考策略优化偏好对，无需显式训练奖励模型并运行 RL 循环 | 是 |
| 推理时计算 | 新任务、生成上下文、候选与检查 | 在既定参数下投入更多计算完成任务 | 通常否 |

RLHF 是一类方法；经典做法训练奖励模型再用强化学习更新策略。DPO 是另一种使用偏好数据的优化方式，不是“把差回答删除后做 SFT”，也不要求接在 RLHF 后面。以上只解释目标，不实现算法。

推理模型通常经过专门训练，以便在回答前进行更充分的推理。推理时可增加推理 token、生成多个候选、搜索或检验，但更多计算不保证每道题更好；要同时测量正确率、成本和时延。输出解释长短也不能直接代表内部推理质量。

第四课脚本用同一问题的几个候选和一个严格的算术检查器演示“生成候选 → 验证 → 选择”。它没有调用大模型、没有训练奖励模型，也不是 DPO 或 RLHF。简单算术可精确检验，开放式回答的 verifier 则可能出错。

对后续 Agent 的联系：模型生成一个工具调用，工具返回结果，再把结果加入上下文继续生成。这仍建立在自回归模型上；工具循环是外部软件逻辑。
